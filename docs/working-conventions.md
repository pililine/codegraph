# 本 Fork 工作约定

## 文档优先原则

凡是超过 20 行的分析、方案、测试结果、风险评估，不要只输出在聊天中，必须写入仓库文件并提交 commit。聊天里只给 5 行以内摘要和文件路径。

适用内容类型：
- 问题分析 / 设计理由 → `docs/`
- 采用计划 / 任务拆分 → `docs/`
- 验证报告 / 测试结果 → `reports/`（按需创建）
- 风险评估 / 优先级矩阵 → `docs/`

## 分支约定

- 所有开发在 `cc/` 前缀分支上进行
- 不直接推送到 `main`
- 每个独立任务单独 commit，可回滚

## Commit 规范

```
docs: <说明>        ← 文档变更
feat: <说明>        ← 新功能
fix: <说明>         ← 问题修复
test: <说明>        ← 测试变更
chore: <说明>       ← 构建/配置变更
```

## Fork 改动标记

对现有源文件的侵入式改动，在改动行附近加注释 `// FORK: <原因>`，方便 upstream rebase 时定位。
